Dynamic Programming

DP = recursion + caching. Solve each subproblem once, store the answer, never recompute it. The hardest — and most rewarding — topic in DSA.

CONCEPT 01

When to Use DP

A problem is a DP candidate if it has: 1) Optimal substructure — optimal solution builds on optimal sub-solutions, and 2) Overlapping subproblems — same subproblems are solved repeatedly.

Recognition pattern: "Minimum/maximum of...", "Number of ways to...", "Can you reach...", "Longest/shortest sequence..." — these are DP.
APPROACH 01

Top-Down: Memoization

Start with recursion, add a cache (memo). Before computing, check if the answer is already stored. Natural and intuitive — write recursion first, add memo second. In Python the memo is just a dict keyed by the subproblem's arguments.

PYTHON — Coin Change (Manual dict Memo)
# How many coins (min) to make amount?
from typing import Dict, List


def coin_change(coins: List[int], amount: int) -> int:
    memo: Dict[int, float] = {}

    def dp(remaining: int) -> float:
        if remaining == 0:
            return 0                 # base: no coins needed
        if remaining < 0:
            return float('inf')      # base: impossible
        if remaining in memo:
            return memo[remaining]   # already solved → O(1) lookup

        best = min(1 + dp(remaining - coin) for coin in coins)

        memo[remaining] = best
        return best

    result = dp(amount)
    return -1 if result == float('inf') else result


print(coin_change([1, 5, 10, 25], 30))  # 2  (25+5)

Python ships the memo for you: functools.lru_cache wraps any function whose arguments are hashable and caches every result. Same algorithm, zero bookkeeping.

PYTHON — Coin Change with @lru_cache
from functools import lru_cache
from typing import List


def coin_change_cached(coins: List[int], amount: int) -> int:

    @lru_cache(maxsize=None)          # unbounded cache = classic memo
    def dp(remaining: int) -> float:
        if remaining == 0:
            return 0
        if remaining < 0:
            return float('inf')
        return min(1 + dp(remaining - coin) for coin in coins)

    result = dp(amount)
    return -1 if result == float('inf') else result


print(coin_change_cached([1, 5, 10, 25], 30))  # 2
print(coin_change_cached([2], 3))                # -1
Python gotchas: @lru_cache needs hashable arguments — pass a tuple, not a list, or key on indices instead. Define the cached function inside the outer function (as above) so the cache is fresh per call. Deep recursion hits Python's default limit of ~1000 frames (RecursionError); raise it with sys.setrecursionlimit(10**6) or, better, switch to bottom-up tabulation. (functools.cache is a 3.9+ shorthand for lru_cache(maxsize=None).)
APPROACH 02

Bottom-Up: Tabulation

Build solutions from the smallest subproblems upward. Fill a table iteratively. Usually faster (no recursion overhead) and avoids RecursionError on deep problems.

PYTHON — Coin Change (Tabulation)
from typing import List


def coin_change_dp(coins: List[int], amount: int) -> int:
    # dp[i] = min coins to make amount i
    INF = float('inf')
    dp = [INF] * (amount + 1)       # 1D list of immutables: [x] * n is safe
    dp[0] = 0                         # base case: 0 coins for amount 0

    # Fill table from 1 to amount
    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], 1 + dp[i - coin])

    return -1 if dp[amount] == INF else dp[amount]


print(coin_change_dp([1, 5], 6))  # 2

# Trace for coins=[1,5], amount=6:
#  i:   0  1  2  3  4  5  6
# dp: [0, 1, 2, 3, 4, 1, 2]
# dp[5] = 1 (one 5-coin), dp[6] = 2 (5+1)
EXAMPLE 01

0/1 Knapsack

Given items with weights and values, maximize value without exceeding capacity. Classic 2D DP — dp[i][w] = max value using first i items with capacity w. In Python, build the 2D table with a list comprehension so every row is its own list.

PYTHON — 0/1 Knapsack
from typing import List


def knapsack(weights: List[int], values: List[int], capacity: int) -> int:
    n = len(weights)
    # dp[i][w] = max value with first i items, capacity w
    dp = [[0] * (capacity + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        wt, val = weights[i - 1], values[i - 1]
        for w in range(capacity + 1):
            # Don't take item i
            dp[i][w] = dp[i - 1][w]

            # Take item i (if it fits)
            if wt <= w:
                dp[i][w] = max(dp[i][w], val + dp[i - 1][w - wt])

    return dp[n][capacity]


print(knapsack([1, 3, 4, 5], [1, 4, 5, 7], 7))  # 9  (weights 3+4)
PYTHON — The [[0]*m]*n Aliasing Trap
# WRONG: the outer * copies the SAME row reference 3 times
bad = [[0] * 3] * 3
bad[0][0] = 1
print(bad)           # [[1, 0, 0], [1, 0, 0], [1, 0, 0]]  ← every row changed!
print(bad[0] is bad[1])  # True — one list, three names

# RIGHT: the comprehension builds a NEW row on every iteration
good = [[0] * 3 for _ in range(3)]
good[0][0] = 1
print(good)          # [[1, 0, 0], [0, 0, 0], [0, 0, 0]]
print(good[0] is good[1])  # False
Why it happens: [0] * m is fine because ints are immutable — reassigning a cell just rebinds it. But [row] * n copies the reference to one mutable list n times. This is the single most common 2D-DP bug in Python. Always write [[0] * (m + 1) for _ in range(n + 1)].
