CONCEPT 01

What is an Array?

An array is a contiguous block of memory that stores elements of the same type, each accessible by an index. In Python, the built-in list is a dynamic array — it grows and shrinks automatically and can hold any type (under the hood it stores contiguous references to objects, so indexing is still O(1)).

MEMORY LAYOUT
  Index:  [  0  ] [  1  ] [  2  ] [  3  ] [  4  ]
  Value:  [ "a" ] [ "b" ] [ "c" ] [ "d" ] [ "e" ]
           ↑
     arr[0] = "a"    ←  O(1) access — instant!
PYTHON — List Basics
# Creating a list (Python's dynamic array)
arr = [1, 2, 3, 4, 5]

# Access by index — O(1)
print(arr[0])    # 1
print(arr[4])    # 5
print(arr[-1])   # 5  ← negative index counts from the end
print(len(arr))  # 5

# Adding / removing
arr.append(6)      # add to end    → O(1) amortized
arr.pop()          # remove end    → O(1)
arr.insert(0, 0)   # add to front  → O(n) (shifts all!)
arr.pop(0)         # remove front  → O(n) — use collections.deque for queues

# Slicing arr[start:stop:step] — returns a NEW list, O(k)
print(arr[1:3])    # [2, 3]   (stop is exclusive)
print(arr[:2])     # [1, 2]
print(arr[-2:])    # [4, 5]   last two
print(arr[::-1])   # [5, 4, 3, 2, 1]  reversed copy

# Modifying in place — del and slice assignment
del arr[1:3]       # removes 2 items at index 1 → [1, 4, 5]
arr[1:1] = [99]    # inserts 99 at index 1 (same as arr.insert(1, 99))
print(arr)         # [1, 99, 4, 5]
PYTHON — Comprehensions, in & enumerate
nums = [3, 1, 4, 1, 5, 9]

# List comprehensions — build a new list in one readable line
squares = [x * x for x in nums]            # [9, 1, 16, 1, 25, 81]
evens = [x for x in nums if x % 2 == 0]     # [4]
grid = [[0] * 3 for _ in range(2)]        # [[0, 0, 0], [0, 0, 0]]
# grid = [[0] * 3] * 2  ← BUG: both rows are the SAME list object
print(squares, evens, grid)

# Membership: `in` on a list is a linear scan → O(n)
print(5 in nums)      # True  (checks every element)
seen = set(nums)     # build once: O(n)
print(5 in seen)      # True  (hash lookup → O(1) average)

# enumerate gives (index, value) — no manual counter needed
for i, x in enumerate(nums[:2]):
    print(i, x)       # 0 3  then  1 1
References vs copies: b = a does NOT copy a list — both names point to the same object, so b.append(1) changes a too. Copy with a[:], a.copy() or list(a) (shallow), or copy.deepcopy(a) for nested lists. Also: x in my_list inside a loop silently makes your solution O(n²) — convert to a set first.
TECHNIQUE 01

Two Pointers

Use two variables (left & right) that start at opposite ends and move toward each other. This converts O(n²) brute-force solutions into O(n). Classic for sorted arrays.

TWO POINTER MOVEMENT
  [  1  ] [  2  ] [  3  ] [  4  ] [  5  ] [  6  ]
     ↑                                       ↑
    left                                   right
    sum = 7  (target=7?) → YES! found it.
EXAMPLE — Two Sum (sorted array)
from typing import List

def two_sum(nums: List[int], target: int) -> List[int]:
    left, right = 0, len(nums) - 1   # tuple unpacking: two assignments in one line

    while left < right:
        total = nums[left] + nums[right]  # don't name it `sum` — that shadows the built-in

        if total == target:
            return [left, right]  # found!
        elif total < target:
            left += 1   # need bigger sum → move left right (Python has no ++)
        else:
            right -= 1  # need smaller sum → move right left

    return []  # no solution

# Example
print(two_sum([1, 2, 3, 4, 6], 6))  # [1, 3]  (2+4=6)
TECHNIQUE 02

Sliding Window

Instead of recalculating a sub-array sum from scratch each step, slide a window — add the new element on the right, subtract the one leaving on the left. Reduces O(n·k) to O(n).

WINDOW SLIDING (window size = 3)
  [  2  ] [  1  ] [  5  ] [  3  ] [  6  ]
  [█████████████████████]                    2+1+5 = 8
          [█████████████████████]            1+5+3 = 9   (+3 −2)
                  [█████████████████████]    5+3+6 = 14  (+6 −1)

  Window sums: 8 → 9 → 14   Max = 14
EXAMPLE — Max subarray sum of size k
from typing import List

def max_sum_window(arr: List[int], k: int) -> int:
    # Build the first window — sum() over a slice, O(k)
    window_sum = sum(arr[:k])
    max_sum = window_sum

    # Slide the window: add right element, drop left element
    for i in range(k, len(arr)):
        window_sum += arr[i] - arr[i - k]
        max_sum = max(max_sum, window_sum)

    return max_sum

print(max_sum_window([2, 1, 5, 3, 6], 3))  # 14  (5+3+6)

# ⚠ Don't do max(sum(arr[i:i+k]) for i in ...) — re-summing each slice is O(n·k)
TECHNIQUE 03

Prefix Sums

Pre-compute cumulative sums so any range sum query runs in O(1). Build once, query many times. Essential for range problems.

EXAMPLE — Range sum query
from itertools import accumulate
from typing import List

def build_prefix(arr: List[int]) -> List[int]:
    prefix = [0]  # prefix[0] = 0 (sentinel)
    for num in arr:
        prefix.append(prefix[-1] + num)  # prefix[-1] = last value so far
    return prefix

# Pythonic one-liner: [0] + list(accumulate(arr))

# Sum of arr[l..r] inclusive = prefix[r+1] - prefix[l]
def range_sum(prefix: List[int], l: int, r: int) -> int:
    return prefix[r + 1] - prefix[l]

arr = [3, 1, 4, 1, 5, 9]
pre = build_prefix(arr)
print(pre)                              # [0, 3, 4, 8, 9, 14, 23]
print([0] + list(accumulate(arr)))      # [0, 3, 4, 8, 9, 14, 23]  same thing
print(range_sum(pre, 1, 4))            # 11 (1+4+1+5)
Key Insight: Most array problems are variants of these three patterns. When you see "subarray", think sliding window or prefix sum. When you see "sorted array + target", think two pointers.
