Day 22 · 90 min

DP — 1D Problems + Memoization

Every DP problem follows one process: define state → find recurrence → set base case → code it. Always start top-down (memoization), then convert to bottom-up if needed.

THE DP LITMUS TEST A problem is DP if it has: (1) overlapping subproblems — same subproblem is solved multiple times, and (2) optimal substructure — optimal solution uses optimal sub-solutions. If both, use DP. If only (2), greedy might work.

Problem 1: Climbing Stairs

You can climb 1 or 2 steps. How many distinct ways to reach the top of n steps?

climbing_stairs.py 
from functools import lru_cache
from typing import Dict, List, Optional


# TOP-DOWN: Memoization with an explicit dict — O(n) time, O(n) space
def climb_stairs_memo(n: int, memo: Optional[Dict[int, int]] = None) -> int:
    if memo is None:
        memo = {}  # never write memo={} as a default — it's shared between calls!
    if n <= 2:
        return n            # base cases
    if n in memo:
        return memo[n]      # already computed?
    memo[n] = climb_stairs_memo(n - 1, memo) + climb_stairs_memo(n - 2, memo)
    return memo[n]


# TOP-DOWN, the Pythonic way: @lru_cache writes the memo for you
@lru_cache(maxsize=None)
def climb_stairs_cached(n: int) -> int:
    if n <= 2:
        return n
    return climb_stairs_cached(n - 1) + climb_stairs_cached(n - 2)


# BOTTOM-UP: Tabulation — O(n) time, O(n) space
def climb_stairs_tab(n: int) -> int:
    if n <= 2:
        return n
    dp = [0] * (n + 1)
    dp[1], dp[2] = 1, 2
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]


# SPACE-OPTIMIZED: O(1) — only need last two values
def climb_stairs(n: int) -> int:
    if n <= 2:
        return n
    prev2, prev1 = 1, 2
    for _ in range(3, n + 1):
        prev2, prev1 = prev1, prev1 + prev2  # tuple assignment: no temp variable
    return prev1


print(climb_stairs_memo(5), climb_stairs_cached(5), climb_stairs_tab(5), climb_stairs(5))  # 8 8 8 8

# DP PROCESS:
# State: dp[i] = number of ways to reach step i
# Recurrence: dp[i] = dp[i-1] + dp[i-2]
# Base: dp[1]=1, dp[2]=2
# This is literally Fibonacci. Recognize it.
PYTHON DP TOOLBOX @lru_cache(maxsize=None) from functools memoizes any function whose arguments are hashable (ints, strings, tuples — not lists; convert with tuple(nums)). float('inf') is the "impossible" sentinel. [0] * (n + 1) builds a 1D table; [[0] * cols for _ in range(rows)] builds a 2D one. Deep top-down recursion can hit the ~1000-frame recursion limit — that's the moment to switch to bottom-up.

Problem 2: House Robber

Rob houses along a street. Can't rob two adjacent houses. Maximize total money.

house_robber.py 
# O(n) time, O(1) space
def rob(nums: List[int]) -> int:
    prev2 = 0  # dp[i-2]
    prev1 = 0  # dp[i-1]

    for num in nums:
        prev2, prev1 = prev1, max(prev1, prev2 + num)
    return prev1


print(rob([2, 7, 9, 3, 1]))  # 12  (2 + 9 + 1)
print(rob([5]))              # 5   (single house works too)

# State: dp[i] = max money robbing houses [0..i]
# Recurrence: dp[i] = max(dp[i-1], dp[i-2] + nums[i])
#   → either skip house i (take dp[i-1])
#   → or rob house i (take dp[i-2] + nums[i])
# This is the "take or skip" DP pattern — appears everywhere.

Problem 3: Coin Change

Given coin denominations and a target amount, find the fewest coins needed.

coin_change.py 
# O(amount × coins) time, O(amount) space
def coin_change(coins: List[int], amount: int) -> int:
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0  # base: 0 coins to make amount 0

    for i in range(1, amount + 1):
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    return -1 if dp[amount] == float('inf') else dp[amount]


print(coin_change([1, 2, 5], 11))  # 3   (5 + 5 + 1)
print(coin_change([2], 3))         # -1

# State: dp[i] = min coins to make amount i
# Recurrence: dp[i] = min(dp[i - coin] + 1) for each coin
# This is "unbounded knapsack" — each coin can be used infinitely.
# float('inf') is the standard "impossible" sentinel (inf + 1 is still inf).
Day 23 · 90 min

DP — 2D Problems

2D DP adds one more dimension of state. The trick: always draw the table first. Fill in base cases, then fill cell by cell. The code writes itself once the table makes sense.

Problem 1: Unique Paths

Robot in top-left of m×n grid, can only move right or down. How many unique paths to bottom-right?

unique_paths.py 
# O(m×n) time, O(m×n) space
def unique_paths(m: int, n: int) -> int:
    dp = [[1] * n for _ in range(m)]  # NOT [[1] * n] * m — that aliases one row m times
    # First row and first column are all 1s (only one way to reach)

    for r in range(1, m):
        for c in range(1, n):
            dp[r][c] = dp[r - 1][c] + dp[r][c - 1]  # from above + from left
    return dp[-1][-1]  # negative index = last row, last column


print(unique_paths(3, 7))  # 28
print(unique_paths(3, 2))  # 3

# State: dp[r][c] = number of paths to reach (r, c)
# Recurrence: dp[r][c] = dp[r-1][c] + dp[r][c-1]
# Base: first row = 1, first col = 1

Problem 2: Longest Common Subsequence

Given two strings, find the length of their longest common subsequence.

lcs.py 
# O(m×n) time and space
def longest_common_subsequence(text1: str, text2: str) -> int:
    m, n = len(text1), len(text2)
    # dp[i][j] = LCS of text1[:i] and text2[:j]
    dp = [[0] * (n + 1) for _ in range(m + 1)]

    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i - 1] == text2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1  # characters match → extend
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])  # skip one
    return dp[m][n]


# Same recurrence, top-down — often the fastest way to write it in an interview
def lcs_memo(text1: str, text2: str) -> int:
    @lru_cache(maxsize=None)
    def solve(i: int, j: int) -> int:
        if i == len(text1) or j == len(text2):
            return 0
        if text1[i] == text2[j]:
            return 1 + solve(i + 1, j + 1)
        return max(solve(i + 1, j), solve(i, j + 1))
    return solve(0, 0)


print(longest_common_subsequence("abcde", "ace"))  # 3  ("ace")
print(lcs_memo("abcde", "ace"))                    # 3
print(longest_common_subsequence("abc", "def"))    # 0

# THE 2D DP TEMPLATE for string comparison:
# Match → take diagonal + 1
# No match → max(skip from string1, skip from string2)
# Applies to: LCS, Edit Distance, Minimum Deletions

Problem 3: Edit Distance

Given two words, find the minimum operations (insert, delete, replace) to convert one into the other.

edit_distance.py 
# O(m×n) time and space
def min_distance(word1: str, word2: str) -> int:
    m, n = len(word1), len(word2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]

    # Base cases: converting to/from empty string
    for i in range(m + 1):
        dp[i][0] = i  # delete all
    for j in range(n + 1):
        dp[0][j] = j  # insert all

    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if word1[i - 1] == word2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]  # match — no operation
            else:
                dp[i][j] = 1 + min(
                    dp[i - 1][j],      # delete
                    dp[i][j - 1],      # insert
                    dp[i - 1][j - 1],  # replace
                )
    return dp[m][n]


print(min_distance("horse", "ros"))           # 3
print(min_distance("intention", "execution"))  # 5

# Same template as LCS but with 3 operations instead of 2.
# Match → diagonal (free). No match → 1 + min(delete, insert, replace).
# Draw the table. Fill it. The code is just the table in code form.
Day 24 · 90 min

DP — Knapsack Variants

The knapsack family: "for each item, choose to include it or not." This pattern appears in partition problems, subset sums, and optimization under constraints.

Problem 1: 0/1 Knapsack

Given weights and values of n items, find the maximum value that fits in a knapsack of capacity W.

knapsack_01.py 
# O(n × W) time, O(n × W) space
def knapsack(weights: List[int], values: List[int], W: int) -> int:
    n = len(weights)
    # dp[i][w] = max value using items [0..i-1] with capacity w
    dp = [[0] * (W + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        wt, val = weights[i - 1], values[i - 1]
        for w in range(W + 1):
            dp[i][w] = dp[i - 1][w]  # skip item i
            if wt <= w:
                dp[i][w] = max(dp[i][w], dp[i - 1][w - wt] + val)  # take it
    return dp[n][W]


print(knapsack([1, 3, 4, 5], [1, 4, 5, 7], 7))  # 9  (weights 3 + 4)

# THE KNAPSACK TEMPLATE:
# For each item: skip it (dp[i-1][w]) OR take it (dp[i-1][w-weight] + value)
# dp[i-1] means each item used at most once (0/1 knapsack)
# dp[i] means items can be reused (unbounded knapsack — like Coin Change)

Problem 2: Partition Equal Subset Sum

Can you partition an array into two subsets with equal sum?

partition_equal_subset.py 
# Transform: can we find a subset that sums to total / 2?
# This IS the 0/1 knapsack with target = sum / 2

# O(n × sum) time, O(sum) space (1D optimization)
def can_partition(nums: List[int]) -> bool:
    total = sum(nums)
    if total % 2 != 0:
        return False  # odd total → impossible

    target = total // 2  # // keeps it an int (/ would give a float)
    dp = [False] * (target + 1)
    dp[0] = True  # sum of 0 is always achievable

    for num in nums:
        # Iterate BACKWARDS to avoid using same item twice
        for j in range(target, num - 1, -1):
            dp[j] = dp[j] or dp[j - num]
    return dp[target]


print(can_partition([1, 5, 11, 5]))  # True   ([1, 5, 5] and [11])
print(can_partition([1, 2, 3, 5]))   # False

# KEY INSIGHT: iterating backwards ensures each number is used once.
# Forward iteration would let you use the same number multiple times.
# This is the 1D space-optimized 0/1 knapsack pattern.
# range(target, num - 1, -1) counts target, target-1, ..., num (stop is exclusive).

Problem 3: Target Sum

Assign + or - to each number to reach a target sum. Count the number of ways.

target_sum.py 
# Transform: P - N = target, P + N = total
# So P = (target + total) / 2
# Count subsets that sum to P → 0/1 knapsack counting

def find_target_sum_ways(nums: List[int], target: int) -> int:
    total = sum(nums)
    if (total + target) % 2 != 0 or abs(target) > total:
        return 0

    P = (total + target) // 2
    dp = [0] * (P + 1)
    dp[0] = 1  # one way to make sum 0: choose nothing

    for num in nums:
        for j in range(P, num - 1, -1):
            dp[j] += dp[j - num]  # add ways that include this number
    return dp[P]


print(find_target_sum_ways([1, 1, 1, 1, 1], 3))  # 5
print(find_target_sum_ways([1], 1))               # 1

# The mathematical transform is the hard part.
# Once you see it's a subset sum counting problem,
# the code is the same knapsack template.

If DP is your weak spot — The Thinking Framework

For every DP problem, answer these 4 questions in order before writing code:

1. What is the state? What variables fully describe a subproblem? (Usually: index into array, remaining capacity/target, or position in grid.) In Python, the state is literally the argument list of your @lru_cache function.

2. What is the recurrence? How does the answer for state (i) relate to smaller states? (Usually: take vs skip, or try all options and take the best.)

3. What is the base case? When is the answer obvious without recursion? (Usually: empty array, zero capacity, or reaching the end.)

4. What is the answer? Which cell in the DP table is the final answer? (Usually: dp[n], dp[n][W], or dp[m][n].)
