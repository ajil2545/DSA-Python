Greedy Algorithms

Take the best-looking choice now and never look back. When it works it beats DP on simplicity and speed — the skill is knowing when it works.

TYPICAL TIME
O(n log n)
SORT-FREE SCAN
O(n)
HEAP STEP
O(log n)
EXTRA SPACE
O(1)–O(n)
Mindset: greedy is a hypothesis, not a technique you apply blindly. Every greedy solution comes with a reason the local choice is safe.
CONCEPT 01

The Greedy Choice Property

A greedy algorithm builds the answer one step at a time and, at every step, takes the choice that looks best right now — it never goes back to reconsider. That only works when the problem has the greedy choice property (some optimal answer starts with the locally best choice) and optimal substructure (after making that choice, what remains is a smaller copy of the same problem).

Greedy vs. DP in one sentence: DP tries every choice and keeps the best; greedy commits to one choice and proves it never needs the others. When you can prove it, greedy is usually simpler and faster (often just a sort plus one pass).

GREEDY = ONE PATH THROUGH THE DECISION TREE
DP explores every branch          Greedy follows one branch
        root                              root
      /  |  \                               |
     a   b   c                             b   ← best-looking choice
    /|\ /|\ /|\                             |
   ...  ...  ...                           b2  ← best-looking again
O(states x choices)               O(n) or O(n log n) after sorting
CONCEPT 02

When Greedy Fails — Coin Change

The classic trap: "to make change, always take the biggest coin that fits". With US coins [1, 5, 10, 25] this happens to be optimal (the system is canonical). With coins [1, 3, 4] and amount 6, greedy takes 4 + 1 + 1 = 3 coins, but 3 + 3 = 2 coins is better. Grabbing the 4 early destroyed a better future — the greedy choice property does not hold, so you need DP.

COINS [1, 3, 4], AMOUNT 6
Greedy (largest first):   6 -4-> 2 -1-> 1 -1-> 0      3 coins  ✗
Optimal (DP):             6 -3-> 3 -3-> 0             2 coins  ✓

dp[a] = 1 + min(dp[a - c] for c in coins if c <= a)
a  :  0  1  2  3  4  5  6
dp :  0  1  2  1  1  2  2
PYTHON — Greedy vs DP Coin Change
from typing import List


def greedy_coins(coins: List[int], amount: int) -> int:
    count = 0
    for coin in sorted(coins, reverse=True):
        take, amount = divmod(amount, coin)   # use as many of this coin as fit
        count += take
    return count if amount == 0 else -1


def dp_coins(coins: List[int], amount: int) -> int:
    INF = float('inf')
    dp = [0] + [INF] * amount               # dp[a] = fewest coins that make a
    for a in range(1, amount + 1):
        for coin in coins:
            if coin <= a:
                dp[a] = min(dp[a], dp[a - coin] + 1)
    return dp[amount] if dp[amount] != INF else -1


print(greedy_coins([1, 5, 10, 25], 63))  # 6  (25+25+10+1+1+1) — optimal for canonical coins
print(greedy_coins([1, 3, 4], 6))        # 3  (4+1+1) — WRONG
print(dp_coins([1, 3, 4], 6))            # 2  (3+3) — DP finds the true optimum
Rule of thumb: before trusting a greedy idea, spend 60 seconds hunting for a small counter-example (2–4 items). If you find one, switch to DP. If every attempt fails, try to prove it with an exchange argument (next section).
CONCEPT 03

Exchange-Argument Intuition

How do you convince yourself (or an interviewer) a greedy choice is safe? The exchange argument: take any optimal solution OPT. If it does not contain your greedy choice g, show you can swap one of its choices for g without making it worse. Then some optimal solution starts with g, and you repeat the argument on the rest.

Example — activity selection (pick the most non-overlapping meetings). Greedy: always take the meeting that ends earliest. Proof sketch: let OPT's first meeting be x. Our pick g ends no later than x, so replacing x with g cannot collide with anything after it. Same count, now starting with g. ✓

SWAP OPT'S FIRST PICK FOR THE EARLIEST-ENDING ONE
time:   0    2    4    6    8    10   12
g       [---------)                       ← ends earliest
x            [---------)                  ← OPT's first choice
next                        [---------)   ← OPT's second choice
g ends no later than x, and x ends before "next" starts → swapping x for g is safe
PYTHON — Activity Selection (Earliest End First)
def max_activities(activities):
    count, last_end = 0, float('-inf')
    for start, end in sorted(activities, key=lambda a: a[1]):   # sort by END time
        if start >= last_end:          # compatible with everything chosen so far
            count += 1
            last_end = end
    return count


meetings = [(1, 4), (3, 5), (0, 6), (5, 7), (3, 9), (5, 9),
            (6, 10), (8, 11), (8, 12), (2, 14), (12, 16)]
print(max_activities(meetings))  # 4  -> (1,4) (5,7) (8,11) (12,16)
Why not sort by start or by length? Earliest start fails on [(0, 100), (1, 2), (3, 4)] (picks 1 instead of 2). Shortest first fails on [(0, 5), (4, 7), (6, 11)] (picks the middle one, which blocks both others). Trying the wrong key against a tiny input is the fastest way to find the right one.
TECHNIQUE 01

Sort-Then-Scan

The most common greedy shape: sort by the quantity that decides priority, then make one pass and take/skip each item. Python makes the sort a one-liner with sorted(items, key=...) and reverse=True; tuples compare lexicographically, so key=lambda x: (-x[1], x[0]) gives "descending by second field, ties ascending by first".

Example — Maximum Units on a Truck: each box type is [count, units_per_box], the truck holds truck_size boxes. Every slot is identical, so fill slots with the most valuable boxes first. Exchange argument: swapping a cheaper box in for a richer one can only lose units.

PYTHON — Maximum Units on a Truck
def maximum_units(box_types, truck_size):
    total = 0
    for boxes, units in sorted(box_types, key=lambda b: b[1], reverse=True):
        take = min(boxes, truck_size)    # take as many of the richest boxes as fit
        total += take * units
        truck_size -= take
        if truck_size == 0:
            break
    return total


print(maximum_units([[1, 3], [2, 2], [3, 1]], 4))               # 8   (3 + 2*2 + 1)
print(maximum_units([[5, 10], [2, 5], [4, 7], [3, 9]], 10))     # 91  (50 + 27 + 14)
Assign Cookies — sort both, match smallest
Activity selection — sort by end
Boats to Save People — sort + two pointers
Non-overlapping Intervals — sort by end
Minimum Arrows to Burst Balloons
Largest Number — custom comparator
Custom comparisons: Python 3's sorted has no cmp argument. When the order is pairwise (e.g. Largest Number: is a + b > b + a as strings?), wrap a two-argument function with functools.cmp_to_key.
TECHNIQUE 02

Running-State Greedy (One Pass, No Sort)

Many array greedies keep a single piece of running state and update it as they scan: the farthest reachable index (Jump Game), the current fuel (Gas Station), or the last index of each character (Partition Labels). The greedy insight is usually "if the running state goes bad here, no earlier starting point can fix it".

JUMP GAME — TRACK THE FARTHEST REACH
index :  0   1   2   3   4
nums  : [2,  3,  1,  1,  4]
reach :  2   4   4   4   8      reach = max(reach, i + nums[i])
if i ever exceeds reach → index i is unreachable → False
PYTHON — Farthest Reach
def can_reach_end(nums):
    reach = 0
    for i, jump in enumerate(nums):
        if i > reach:              # we can never stand on index i
            return False
        reach = max(reach, i + jump)
    return True


print(can_reach_end([2, 3, 1, 1, 4]))  # True
print(can_reach_end([3, 2, 1, 0, 4]))  # False (stuck at index 3)
TECHNIQUE 03

Heap-Driven Greedy

When the "best choice right now" changes as you go (new items arrive, combined items re-enter the pool), sorting once is not enough — keep the candidates in a heap and pop the best each step. Python's heapq is a min-heap on a plain list: heappush, heappop, heapify (O(n)) and heapreplace. For a max-heap, push negated values.

Example — Minimum Cost to Connect Sticks: joining sticks of length a and b costs a + b. Always join the two shortest sticks (this is exactly Huffman coding): long sticks get added into the total fewer times.

STICKS [1, 8, 3, 5]
heap [1, 3, 5, 8]  pop 1, 3 → push 4    cost  4
heap [4, 5, 8]     pop 4, 5 → push 9    cost  9   (total 13)
heap [8, 9]        pop 8, 9 → push 17   cost 17   (total 30)
PYTHON — Connect Sticks with heapq
import heapq


def connect_sticks(sticks):
    heap = list(sticks)            # copy so we don't mutate the caller's list
    heapq.heapify(heap)            # O(n)
    cost = 0
    while len(heap) > 1:
        a = heapq.heappop(heap)    # two cheapest sticks
        b = heapq.heappop(heap)
        cost += a + b
        heapq.heappush(heap, a + b)
    return cost


print(connect_sticks([2, 4, 3]))     # 14
print(connect_sticks([1, 8, 3, 5]))  # 30
PYTHON — Max-Heap by Negation (Last Stone Weight)
import heapq


def last_stone_weight(stones):
    heap = [-s for s in stones]    # negate: heapq only gives the minimum
    heapq.heapify(heap)
    while len(heap) > 1:
        first = -heapq.heappop(heap)   # heaviest
        second = -heapq.heappop(heap)  # second heaviest
        if first != second:
            heapq.heappush(heap, -(first - second))
    return -heap[0] if heap else 0


print(last_stone_weight([2, 7, 4, 1, 8, 1]))  # 1
Interview checklist for greedy: (1) state the greedy rule in one sentence, (2) try to break it with a tiny example, (3) give the exchange-argument sketch, (4) code it — usually a sort or a heap plus one loop.
