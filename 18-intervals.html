Intervals [start, end]

Calendars, bookings, CPU jobs, genome ranges. Sort first, then one scan — with the right overlap test and a heap or sweep line when you need to count concurrency.

SORT
O(n log n)
MERGE SCAN
O(n)
HEAP / SWEEP
O(n log n)
SPACE
O(n)
Pattern trigger: input is a list of pairs with start/end times, or the problem says overlap, merge, schedule, booking, rooms or free time.
CONCEPT 01

Representing Intervals in Python

An interval is just a pair [start, end]. LeetCode passes a list of lists; in your own code a tuple is often nicer because it is immutable and hashable (usable as a dict key or set member). Unpack the pair directly in the loop header — for start, end in intervals — instead of indexing iv[0] and iv[1] everywhere.

Always pin down the convention: closed [1, 4] includes 4, so [1, 4] and [4, 6] overlap; half-open [1, 4) excludes it, so a meeting ending at 4 and one starting at 4 do not clash. Meeting-room problems are half-open; Merge Intervals is closed. It only changes < vs <= — and that is exactly where bugs hide.

PYTHON — Intervals as Lists, Tuples and namedtuples
from collections import namedtuple
from typing import List, Tuple

intervals: List[List[int]] = [[1, 3], [8, 10], [2, 6], [15, 18]]
meetings: List[Tuple[int, int]] = [(9, 10), (13, 15)]

for start, end in meetings:              # unpack instead of m[0], m[1]
    print(start, end, "length", end - start)
# 9 10 length 1
# 13 15 length 2

Interval = namedtuple("Interval", ["start", "end"])
iv = Interval(2, 6)
print(iv.start, iv.end, iv)  # 2 6 Interval(start=2, end=6)
CONCEPT 02

Sort by Start — The First Line of Almost Every Solution

Unsorted intervals can overlap in any order. Once sorted by start, any interval can only overlap the ones right before it, which turns most problems into a single left-to-right scan. list.sort(key=...) sorts in place and returns None; sorted(...) returns a new list and leaves the input untouched. Both are stable O(n log n) Timsort.

PYTHON — Sorting Intervals
intervals = [[1, 3], [8, 10], [2, 6], [15, 18]]

intervals.sort(key=lambda x: x[0])          # in place, by start
print(intervals)  # [[1, 3], [2, 6], [8, 10], [15, 18]]

by_end = sorted(intervals, key=lambda x: x[1])   # new list, by end (greedy problems)
print(by_end)     # [[1, 3], [2, 6], [8, 10], [15, 18]]

# Lists/tuples compare element by element, so a plain sort is "by start, then by end"
print(sorted([(5, 9), (1, 4), (1, 2)]))     # [(1, 2), (1, 4), (5, 9)]

# operator.itemgetter is a slightly faster alternative to the lambda
from operator import itemgetter
print(sorted([[3, 4], [0, 9]], key=itemgetter(0)))  # [[0, 9], [3, 4]]
Sort by start or by end? Start when you are building merged blocks (merge, insert, meeting rooms). End when you are choosing a maximum set of non-overlapping intervals (greedy: Non-overlapping Intervals, Min Arrows).
CONCEPT 03

The Overlap Condition

Two closed intervals a and b overlap exactly when a.start <= b.end and b.start <= a.end. It's easier to remember the opposite: they are disjoint when one ends before the other starts. The overlapping part, if any, is [max(starts), min(ends)].

OVERLAP CASES (a = top, b = bottom)
overlap        a: [-------]            disjoint     a: [---]
               b:      [-------]                    b:         [---]
               max(start) <= min(end)               a.end < b.start

contained      a: [-------------]      touching     a: [----]
               b:     [---]                         b:      [----]
               still overlaps                       closed: overlap  half-open: no
PYTHON — Overlap and Intersection
from typing import List, Optional


def overlaps(a: List[int], b: List[int]) -> bool:
    return a[0] <= b[1] and b[0] <= a[1]


def intersection(a: List[int], b: List[int]) -> Optional[List[int]]:
    lo, hi = max(a[0], b[0]), min(a[1], b[1])
    return [lo, hi] if lo <= hi else None


print(overlaps([1, 5], [4, 8]))      # True
print(overlaps([1, 3], [4, 6]))      # False
print(overlaps([1, 4], [4, 6]))      # True  (closed intervals: touching counts)
print(intersection([1, 5], [4, 8]))  # [4, 5]
print(intersection([1, 3], [4, 6]))  # None
Once sorted by start, you only need half the test: the next interval overlaps the current block iff next.start <= current.end (its start is already >= the block's start).
TECHNIQUE 01

Merge Overlapping Intervals

Sort by start, then keep a merged list whose last element is the block you are growing. For each interval: if it overlaps the last block, stretch the block's end; otherwise it starts a new block. Use max when stretching — a short interval inside a long one must not shrink it.

MERGE [[1,3], [2,6], [8,10], [15,18]]
                                                    merged
[---]                                               [1,3]
  [-------]  2 <= 3 → stretch to 6                  [1,6]
              [---]  8 > 6 → new                    [1,6] [8,10]
                            [-----]  15 > 10 → new  [1,6] [8,10] [15,18]
1 2 3     6   8   10        15    18
PYTHON — Merge
from typing import List


def merge(intervals: List[List[int]]) -> List[List[int]]:
    merged: List[List[int]] = []
    for start, end in sorted(intervals, key=lambda x: x[0]):
        if merged and start <= merged[-1][1]:       # overlaps the last block
            merged[-1][1] = max(merged[-1][1], end)
        else:
            merged.append([start, end])              # new list: never alias the input
    return merged


print(merge([[1, 3], [2, 6], [8, 10], [15, 18]]))  # [[1, 6], [8, 10], [15, 18]]
print(merge([[1, 4], [2, 3]]))                     # [[1, 4]]  (max keeps the 4)
TECHNIQUE 02

Insert into a Sorted, Non-Overlapping List

When the list is already sorted and disjoint you don't need to sort again — do it in O(n) with three phases: copy everything that ends before the new interval starts, absorb everything that overlaps it (growing the new interval), then copy the rest.

INSERT [4, 8] INTO [[1,2], [3,5], [6,7], [8,10], [12,16]]
phase 1 (end < 4)          : [1,2]
phase 2 (start <= 8)       : [3,5] [6,7] [8,10]  → absorbed → [3,10]
phase 3 (rest)             : [12,16]
result                     : [[1,2], [3,10], [12,16]]
PYTHON — Insert (Three Phases)
from typing import List


def insert(intervals: List[List[int]], new: List[int]) -> List[List[int]]:
    result, i, n = [], 0, len(intervals)
    start, end = new
    while i < n and intervals[i][1] < start:     # 1. entirely to the left
        result.append(intervals[i])
        i += 1
    while i < n and intervals[i][0] <= end:      # 2. overlapping: absorb
        start = min(start, intervals[i][0])
        end = max(end, intervals[i][1])
        i += 1
    result.append([start, end])
    result.extend(intervals[i:])                 # 3. entirely to the right
    return result


print(insert([[1, 2], [3, 5], [6, 7], [8, 10], [12, 16]], [4, 8]))  # [[1, 2], [3, 10], [12, 16]]
bisect shortcut: because the list is sorted and disjoint (so the ends are sorted too), bisect.bisect_left can find phase 1's boundary in O(log n) — but building the output list is still O(n), so the simple loop is the interview answer.
TECHNIQUE 03

Sweep Line with Events

Turn every interval into two events: (start, +1) and (end, -1). Sort the events and sweep left to right keeping a running sum — the sum at any moment is the number of intervals active at that time. Its maximum answers "how many overlap at once?" (rooms, CPUs, peak load).

Tie-breaking is free in Python: tuples compare element by element, so (10, -1) sorts before (10, 1). An end at time t is processed before a start at t — the half-open convention, where a meeting ending at 10 frees its room for one starting at 10.

EVENTS FOR [[0,30], [5,10], [15,20]]
time   0    5    10   15   20   30
event  +1   +1   -1   +1   -1   -1
active 1    2    1    2    1    0        peak = 2
PYTHON — Max Concurrent Intervals (Sweep Line)
from typing import List


def max_overlap(intervals: List[List[int]]) -> int:
    events = []
    for start, end in intervals:
        events.append((start, 1))
        events.append((end, -1))
    events.sort()                  # ties: (t, -1) before (t, 1) → end frees before start
    active = peak = 0
    for _, delta in events:
        active += delta
        peak = max(peak, active)
    return peak


print(max_overlap([[0, 30], [5, 10], [15, 20]]))          # 2
print(max_overlap([[1, 5], [2, 6], [4, 8], [5, 9]]))      # 3
Difference array variant: when times are small integers, skip sorting — do diff[start] += 1; diff[end] -= 1 and take a running sum with itertools.accumulate(diff). Same idea, O(n + range).
TECHNIQUE 04

Min-Heap of End Times (Meeting Rooms)

Another way to count rooms that also tells you which room frees up first. Sort meetings by start and keep a min-heap of end times — one entry per room in use. For each meeting, if the earliest-ending room is free (heap[0] <= start), reuse it; otherwise open a new room. The heap's final size is the number of rooms.

MEETINGS SORTED BY START: [0,30] [5,10] [15,20]
[0,30]   heap empty          → open room     heap [30]
[5,10]   heap[0]=30 > 5      → open room     heap [10, 30]
[15,20]  heap[0]=10 <= 15    → reuse room    heap [20, 30]
rooms = len(heap) = 2
PYTHON — Rooms via heapq
import heapq
from typing import List


def min_rooms(intervals: List[List[int]]) -> int:
    ends: List[int] = []                      # min-heap: end time of each busy room
    for start, end in sorted(intervals):
        if ends and ends[0] <= start:         # earliest-free room is available
            heapq.heapreplace(ends, end)      # pop + push in one O(log n) step
        else:
            heapq.heappush(ends, end)         # need another room
    return len(ends)


print(min_rooms([[0, 30], [5, 10], [15, 20]]))  # 2
print(min_rooms([[7, 10], [2, 4]]))             # 1
