Union-Find DSU

Disjoint Set Union: merge groups and ask "same group?" in near-constant time. The engine behind connected components, cycle detection and Kruskal's MST.

FIND
O(α(n))
UNION
O(α(n))
BUILD
O(n)
SPACE
O(n)
Pattern trigger: "are these connected?", "how many groups?", edges arriving one by one, or "merge items that share something". If you only need connectivity — not paths — reach for DSU.
CONCEPT 01

The Problem It Solves

You have n items and a stream of statements "a and b are connected". At any moment you want to answer "are x and y in the same group?" and "how many groups are there?". Re-running BFS/DFS after every new edge costs O(V + E) each time. A Disjoint Set Union (DSU, a.k.a. Union-Find) answers both in near-constant time, and edges can arrive one by one (online).

It supports exactly two operations: find(x) — return the representative (root) of x's group — and union(a, b) — merge the groups of a and b. Two items are connected iff find(a) == find(b). It cannot split groups; if you need deletions, look elsewhere.

Connected components in a graph
Cycle detection in undirected graphs
Kruskal's minimum spanning tree
Grouping equal items (accounts, synonyms)
Percolation / islands added over time
Equations like a == b, b != c
CONCEPT 02

The Parent Array

Each group is stored as a tree drawn upwards: every node points to its parent, and the root points to itself. All you need is one list, parent = list(range(n)) — initially every node is its own group. find follows parent pointers to the root; union hangs one root under the other.

AFTER union(0,1), union(1,2), union(3,4) — parent = [1, 2, 2, 4, 4, 5]
index :  0  1  2  3  4  5
parent:  1  2  2  4  4  5

     2           4        5
     |           |
     1           3        (three groups: {0,1,2} {3,4} {5})
     |
     0
PYTHON — Naive Parent Array
n = 6
parent = list(range(n))        # [0, 1, 2, 3, 4, 5] — everyone is a root


def find_naive(x: int) -> int:
    while parent[x] != x:      # walk up until a node points to itself
        x = parent[x]
    return x


def union_naive(a: int, b: int) -> None:
    parent[find_naive(a)] = find_naive(b)   # hang a's root under b's root


union_naive(0, 1)
union_naive(1, 2)
union_naive(3, 4)
print(parent)                              # [1, 2, 2, 4, 4, 5]
print(find_naive(0) == find_naive(2))      # True
print(find_naive(0) == find_naive(3))      # False
Why naive is slow: unions like (0,1), (1,2), (2,3), ... can build a chain of height n, so find becomes O(n). The two fixes below — path compression and union by rank/size — flatten the trees.
TECHNIQUE 01

Find with Path Compression

While walking up to the root, re-point every node on the path directly at the root. The next find on any of them is a single hop. The recursive version is the shortest to write; the iterative version avoids Python's recursion limit (default sys.getrecursionlimit() == 1000), which a long chain can blow before compression kicks in.

find(0) ON A CHAIN 0 → 1 → 2 → 3 → 4
before              after find(0)
  4                       4
  |                 / / |  \
  3                0 1  2   3
  |
  2                every node on the path now points at the root
  |
  1
  |
  0
PYTHON — Recursive Path Compression
parent = [1, 2, 3, 4, 4]           # chain: 0 → 1 → 2 → 3 → 4 (root)


def find(x: int) -> int:
    if parent[x] != x:
        parent[x] = find(parent[x])    # point x straight at the root
    return parent[x]


print(find(0))   # 4
print(parent)    # [4, 4, 4, 4, 4]
PYTHON — Iterative (Two-Pass) and Path Halving
from typing import List


def find_iterative(parent: List[int], x: int) -> int:
    root = x
    while parent[root] != root:        # pass 1: locate the root
        root = parent[root]
    while x != root:                   # pass 2: re-point the whole path
        nxt = parent[x]
        parent[x] = root
        x = nxt
    return root


def find_halving(parent: List[int], x: int) -> int:
    while parent[x] != x:
        parent[x] = parent[parent[x]]  # skip to grandparent: halves the path each time
        x = parent[x]
    return x


p = [1, 2, 3, 4, 4]
print(find_iterative(p, 0), p)   # 4 [4, 4, 4, 4, 4]
q = [1, 2, 3, 4, 4]
print(find_halving(q, 0), q)     # 4 [2, 2, 4, 4, 4]
TECHNIQUE 02

Union by Rank / Size

When merging two trees, always hang the smaller tree under the larger root. Union by size tracks node counts; union by rank tracks an upper bound on height. Either guarantees tree height O(log n) on its own, and size has a bonus: size[find(x)] tells you how big x's group is.

union(a, b) — SMALL TREE GOES UNDER BIG ROOT
  A (size 4)      B (size 2)              A (size 6)
 /|\              |              →      /|\  \
. . .             .                    . . .   B
                                               |
                                               .
the smaller tree sinks one level; with union by rank, rank grows only when two equal-rank trees merge
PYTHON — Union by Size and by Rank
n = 6
parent = list(range(n))
size = [1] * n
rank = [0] * n


def find(x: int) -> int:
    if parent[x] != x:
        parent[x] = find(parent[x])
    return parent[x]


def union_by_size(a: int, b: int) -> bool:
    ra, rb = find(a), find(b)
    if ra == rb:
        return False                  # already in the same group
    if size[ra] < size[rb]:
        ra, rb = rb, ra               # make ra the bigger root
    parent[rb] = ra
    size[ra] += size[rb]
    return True


def union_by_rank(a: int, b: int) -> bool:
    ra, rb = find(a), find(b)
    if ra == rb:
        return False
    if rank[ra] < rank[rb]:
        ra, rb = rb, ra
    parent[rb] = ra
    if rank[ra] == rank[rb]:          # equal heights: the result is one taller
        rank[ra] += 1
    return True


union_by_size(0, 1)
union_by_size(2, 3)
union_by_size(0, 2)
print(parent)                  # [0, 0, 0, 2, 4, 5]
print(size[find(3)])           # 4  (group {0, 1, 2, 3})
print(union_by_size(1, 3))     # False (already connected)
CONCEPT 03

Near-O(1) Amortized: Inverse Ackermann

With both path compression and union by rank/size, any sequence of m operations on n elements takes O(m · α(n)), where α is the inverse Ackermann function. α grows so slowly that α(n) ≤ 4 for every n you could ever store — so treat each operation as amortized O(1). (Amortized: an individual find can still walk a few levels, but the total work is bounded.)

COST PER OPERATION
version                               find (worst / amortized)
naive parent array                    O(n)
union by rank/size only               O(log n)
path compression only                 O(log n) amortized
both                                  O(α(n))  ≈ O(1)    α(n) <= 4 for any n you could ever store
In interviews say: "near-constant, inverse Ackermann amortized" and move on. In practice, path compression alone is usually fast enough — but writing union by size costs two extra lines.
TECHNIQUE 03

A Reusable DSU Class

Wrap it up once and reuse it everywhere. This version uses iterative path halving (no recursion limit issues), union by size, keeps a live count of components, and returns True/False from union so callers can tell whether the edge actually merged two groups.

PYTHON — DSU Class
from typing import List


class DSU:
    def __init__(self, n: int):
        self.parent: List[int] = list(range(n))
        self.size: List[int] = [1] * n
        self.count = n                    # number of disjoint groups

    def find(self, x: int) -> int:
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]   # path halving
            x = self.parent[x]
        return x

    def union(self, a: int, b: int) -> bool:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                  # same group: nothing to merge
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra              # smaller tree under bigger root
        self.size[ra] += self.size[rb]
        self.count -= 1
        return True

    def connected(self, a: int, b: int) -> bool:
        return self.find(a) == self.find(b)

    def group_size(self, x: int) -> int:
        return self.size[self.find(x)]


dsu = DSU(5)
dsu.union(0, 1)
dsu.union(3, 4)
print(dsu.connected(0, 1), dsu.connected(1, 3))  # True False
print(dsu.count, dsu.group_size(4))              # 3 2
PYTHON — Dict-Based DSU for Any Hashable Keys
class KeyDSU:
    def __init__(self):
        self.parent = {}                  # created lazily: no need to know n up front

    def find(self, x):
        self.parent.setdefault(x, x)
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b) -> bool:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        self.parent[ra] = rb
        return True


words = KeyDSU()
for a, b in [("great", "fine"), ("fine", "good"), ("bad", "poor")]:
    words.union(a, b)
print(words.find("great") == words.find("good"))  # True
print(words.find("great") == words.find("poor"))  # False
TECHNIQUE 04

Counting Components

Start with n groups and union along every edge — each successful union removes exactly one group, so the answer is dsu.count. Without a counter, count the distinct roots: len({dsu.find(i) for i in range(n)}).

PYTHON — Components from an Edge List
def components(n, edges):
    dsu = DSU(n)                          # the class above
    for u, v in edges:
        dsu.union(u, v)
    return dsu.count, len({dsu.find(i) for i in range(n)})


print(components(6, [[0, 1], [1, 2], [3, 4]]))   # (3, 3)  {0,1,2} {3,4} {5}
TECHNIQUE 05

Cycle Detection (Undirected)

Process edges one at a time. If an edge's endpoints are already connected, adding it closes a loop. That is exactly when union returns False. (For directed graphs use DFS colouring or topological sort instead — DSU ignores direction.)

EDGES 0-1, 1-2, 2-0
0-1 : find(0)=0, find(1)=1 → merge          {0,1} {2}
1-2 : find(1)=0, find(2)=2 → merge          {0,1,2}
2-0 : find(2)=0, find(0)=0 → same root!     cycle ✓
PYTHON — has_cycle
def has_cycle(n, edges):
    dsu = DSU(n)
    for u, v in edges:
        if not dsu.union(u, v):           # endpoints already connected
            return True
    return False


print(has_cycle(4, [[0, 1], [1, 2], [2, 3]]))  # False
print(has_cycle(4, [[0, 1], [1, 2], [2, 0]]))  # True
TECHNIQUE 06

Kruskal's Minimum Spanning Tree

An MST connects all n vertices with n - 1 edges of minimum total weight. Kruskal's algorithm is greedy + DSU: sort edges by weight, and take each edge unless it would form a cycle (its endpoints are already connected). Stop after n - 1 edges. Sorting dominates: O(E log E).

EDGES (w, u, v): (1,0,1) (2,1,3) (3,1,2) (4,0,2) (5,2,3)
     1              take (1,0,1)  ✓  total 1
0 ------- 1         take (2,1,3)  ✓  total 3
 \      / \         take (3,1,2)  ✓  total 6   (n - 1 = 3 edges → stop)
4 \  3 /   \ 2      (4,0,2)  ✗  would be skipped: 0 and 2 already connected
   \  /     \       (5,2,3)  ✗  would be skipped: 2 and 3 already connected
    2 ------- 3
         5
PYTHON — Kruskal with DSU
def kruskal(n, edges):
    dsu = DSU(n)
    total, mst = 0, []
    for w, u, v in sorted(edges):         # tuples sort by weight first
        if dsu.union(u, v):               # skip edges that would form a cycle
            total += w
            mst.append((u, v, w))
            if len(mst) == n - 1:
                break
    return total, mst


edges = [(1, 0, 1), (4, 0, 2), (3, 1, 2), (2, 1, 3), (5, 2, 3)]
print(kruskal(4, edges))  # (6, [(0, 1, 1), (1, 3, 2), (1, 2, 3)])
Kruskal vs Prim: Kruskal (sort + DSU) shines on sparse edge lists. Prim (grow from one vertex with a heapq of crossing edges) is often simpler on dense graphs or adjacency lists. Both are greedy, both proven by the cut property.
