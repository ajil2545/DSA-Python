Sorting Algorithms

Every programmer must understand sorting. Learn the naive O(n²) ones to understand why O(n log n) algorithms are brilliant — then master Python's built-in sorted().

ALGORITHM 01

Bubble Sort — O(n²)

Repeatedly bubble the largest unsorted element to the end by swapping adjacent pairs. Simple to understand, terrible in practice. Only use it to explain why we need better algorithms.

BUBBLE SORT VISUALIZATION
  Pass 1: [5, 3, 8, 1]  →  compare pairs, swap if out of order
          [3, 5, 8, 1]  →  [3, 5, 1, 8]  ← 8 "bubbled" to end

  Pass 2: [3, 5, 1, 8]  →  [3, 1, 5, 8]  ← 5 in place

  Pass 3: [3, 1, 5, 8]  →  [1, 3, 5, 8]  ✓ sorted!
PYTHON — Bubble Sort
from typing import List

def bubble_sort(arr: List[int]) -> List[int]:
    n = len(arr)

    for i in range(n - 1):
        swapped = False

        for j in range(n - i - 1):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]  # swap via tuple unpacking
                swapped = True

        # If no swaps this pass, the list is already sorted
        if not swapped:
            break

    return arr

print(bubble_sort([5, 3, 8, 1]))  # [1, 3, 5, 8]
ALGORITHM 02

Merge Sort — O(n log n)

Divide and conquer — split the list in half recursively until single elements, then merge them back in sorted order. Stable, predictable O(n log n) in every case, and used in production — Python's own Timsort is built on the same merge step. Great for linked lists too.

DIVIDE & MERGE
  [8, 3, 5, 1]
  ↓ split
  [8, 3]    [5, 1]
  ↓ split    ↓ split
  [8] [3]   [5] [1]
  ↓ merge    ↓ merge
  [3, 8]    [1, 5]
  ↓ merge
  [1, 3, 5, 8]  ✓
PYTHON — Merge Sort
from typing import List

def merge_sort(arr: List[int]) -> List[int]:
    # Base case: 0 or 1 element is already sorted
    if len(arr) <= 1:
        return arr

    # Split in half — // is integer (floor) division
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])     # slicing makes a copy
    right = merge_sort(arr[mid:])

    # Merge two sorted halves
    return merge(left, right)


def merge(left: List[int], right: List[int]) -> List[int]:
    result = []
    i = j = 0

    # Pick the smaller element from each half
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:          # <= (not <) keeps the sort STABLE
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1

    # Append remaining elements (at most one side has leftovers)
    result.extend(left[i:])
    result.extend(right[j:])
    return result

print(merge_sort([8, 3, 5, 1]))  # [1, 3, 5, 8]
ALGORITHM 03

Quick Sort — O(n log n) avg

Pick a pivot, put everything smaller on its left and everything larger on its right, then recursively sort each side. Extremely fast in practice — C++'s std::sort uses a variant (introsort). Python's built-in sort is not quicksort, though — it's Timsort (see below).

PYTHON — Quick Sort (in place, Lomuto partition)
from typing import List, Optional

def quick_sort(arr: List[int], low: int = 0, high: Optional[int] = None) -> List[int]:
    if high is None:          # defaults can't refer to other params → None sentinel
        high = len(arr) - 1
    if low < high:
        pivot = partition(arr, low, high)
        quick_sort(arr, low, pivot - 1)    # sort left of pivot
        quick_sort(arr, pivot + 1, high)   # sort right of pivot
    return arr


def partition(arr: List[int], low: int, high: int) -> int:
    pivot = arr[high]   # use last element as pivot
    i = low - 1         # i tracks where to place smaller elements

    for j in range(low, high):
        if arr[j] <= pivot:
            i += 1
            arr[i], arr[j] = arr[j], arr[i]   # swap

    # Put pivot in its correct position
    arr[i + 1], arr[high] = arr[high], arr[i + 1]
    return i + 1        # return pivot index

print(quick_sort([3, 6, 8, 10, 1, 2]))  # [1, 2, 3, 6, 8, 10]
Worst case: O(n²) when the pivot is always the smallest or largest (e.g., sorted input). Fix: use a random pivot (random.randint(low, high), swap it to the end) or "median of three". In Python the degenerate case also recurses n levels deep and hits the default recursion limit (~1000) with a RecursionError.
ALGORITHM 04

Python Built-in Sort — Timsort

In interviews, use the built-ins freely. sorted(iterable) returns a new list; list.sort() sorts in place and returns None. Both use Timsort (a merge sort + insertion sort hybrid): O(n log n) worst case, O(n) on already-sorted data, and stable — equal elements keep their original order. Values are compared with <, so numbers sort numerically with no comparator needed. Customise with key= and reverse=.

PYTHON — sorted(), list.sort(), key=, reverse=
nums = [10, 9, 2]

# sorted() returns a NEW list; the original is untouched
print(sorted(nums))                   # [2, 9, 10]
print(nums)                           # [10, 9, 2]

# list.sort() sorts IN PLACE and returns None
nums.sort()
print(nums)                           # [2, 9, 10]  ascending
nums.sort(reverse=True)
print(nums)                           # [10, 9, 2]  descending
# ❌ Classic bug: result = nums.sort()   → result is None!

# key= : sort by a computed value (called once per element)
words = ["banana", "kiwi", "Fig", "cherry", "apple"]
print(sorted(words))                  # ['Fig', 'apple', 'banana', 'cherry', 'kiwi']  uppercase first!
print(sorted(words, key=str.lower))   # ['apple', 'banana', 'cherry', 'Fig', 'kiwi']
print(sorted(words, key=len))         # ['Fig', 'kiwi', 'apple', 'banana', 'cherry']

# Sort records by a field — stability in action
people = [("Charlie", 30), ("Alice", 25), ("Bob", 30)]
print(sorted(people, key=lambda p: p[1]))
# [('Alice', 25), ('Charlie', 30), ('Bob', 30)]  ← Charlie stays before Bob (stable)

# Multi-key: age DESC, then name ASC — return a tuple, negate the number
print(sorted(people, key=lambda p: (-p[1], p[0])))
# [('Bob', 30), ('Charlie', 30), ('Alice', 25)]
PYTHON — comparator functions with functools.cmp_to_key
from functools import cmp_to_key

# Some orderings can't be expressed as a key — e.g. "Largest Number":
# put a before b if a+b makes a bigger string than b+a.
def by_concat(a: str, b: str) -> int:
    if a + b > b + a:
        return -1      # negative → a comes first
    if a + b < b + a:
        return 1       # positive → b comes first
    return 0

digits = ["3", "30", "34", "5", "9"]
print("".join(sorted(digits, key=cmp_to_key(by_concat))))  # 9534330
Prefer key= over comparators. A key function runs once per element (n calls); a comparator runs on every comparison (n log n calls). Reach for cmp_to_key only when the order truly depends on comparing two items together. Mixing incomparable types (e.g. [1, "a"]) raises TypeError rather than silently producing a strange order.
