CONCEPT 01

Big-O Notation

Big-O describes how the number of steps grows as the input size n grows. We ignore constant factors and small terms and keep only the dominant one, because for large n that is all that matters. It is an upper bound on the growth rate — usually quoted for the worst case.

GROWTH OF COMMON COMPLEXITIES (operations for input size n)
                n = 10        n = 1 000         n = 1 000 000
  O(1)          1             1                 1                  constant
  O(log n)      3             10                20                 halving
  O(n)          10            1 000             1 000 000          one pass
  O(n log n)    33            10 000            20 000 000         good sort
  O(n²)         100           1 000 000         10¹²   ✗ hours     all pairs
  O(2ⁿ)         1 024         10³⁰¹  ✗          ✗                  all subsets

  O(1)        █
  O(log n)    ██
  O(n)        ██████
  O(n log n)  ████████████
  O(n²)       ████████████████████████████████████
  O(2ⁿ)       ██████████████████████████████████████████████████████ → ∞

One function per class. Read the comment on each def line, then convince yourself why by looking at the loop structure.

PYTHON — One Example of Each Complexity
def get_first(nums):          # O(1): one step, whatever len(nums) is
    return nums[0]

def halvings(n):              # O(log n): n is halved every iteration
    steps = 0
    while n > 1:
        n //= 2
        steps += 1
    return steps

def total(nums):              # O(n): touches each element once
    s = 0
    for x in nums:
        s += x
    return s

def sort_copy(nums):          # O(n log n): Timsort, Python's built-in sort
    return sorted(nums)

def count_pairs(nums):        # O(n²): looks at every pair (i, j)
    count = 0
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            count += 1
    return count

def fib(n):                   # O(2ⁿ): each call makes two more calls
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

nums = [5, 3, 8, 1]
print(get_first(nums))          # 5
print(halvings(1024))           # 10
print(total(nums))              # 17
print(sort_copy(nums))          # [1, 3, 5, 8]
print(count_pairs(nums))        # 6
print(fib(20))                  # 6765
Big-O, Big-Ω, Big-Θ: interviewers say “Big-O” loosely to mean the tight bound. Strictly, O is an upper bound, Ω a lower bound and Θ both. Also state which case: dict lookup is O(1) average but O(n) worst case; quicksort is O(n log n) average, O(n²) worst.
CONCEPT 02

How to Count Operations

To find the complexity of code, count how many times the innermost work runs, as a function of the input size. Five rules cover almost everything:

RULES FOR COUNTING OPERATIONS
  1. Sequential blocks ADD        loop n  then loop n        →  O(n + n)  = O(n)
  2. Nested loops MULTIPLY        loop n  inside loop n      →  O(n · n)  = O(n²)
  3. Drop constants               3n + 5                     →  O(n)
  4. Keep the dominant term       n² + n log n + 100         →  O(n²)
  5. Different inputs, different  loop over a, then over b   →  O(a + b)
     variables                    loop over b inside a       →  O(a · b)

  Halving / doubling loop  (i //= 2, i *= 2)                 →  O(log n)
  Recursion: (calls per level) ^ (depth)  e.g. 2 calls, depth n → O(2ⁿ)

The trap in Python is that one innocent-looking line can hide a loop. x in some_list, some_list.index(x), list.pop(0), list.insert(0, x), slicing a[i:j], sorted(), sum(), min()/max() and s1 + s2 on strings are all O(n) or worse — put one inside a loop and your O(n) becomes O(n²).

PYTHON — Spot the Hidden Loop
def has_duplicate_slow(nums):         # O(n²) time, O(1) extra space
    for i in range(len(nums)):            # n iterations
        for j in range(i + 1, len(nums)): #   × up to n
            if nums[i] == nums[j]:
                return True
    return False

def has_duplicate_fast(nums):         # O(n) time, O(n) extra space
    seen = set()
    for x in nums:                    # n iterations
        if x in seen:                 #   × O(1) average set lookup
            return True
        seen.add(x)
    return False

def dedupe_hidden_quadratic(nums):    # looks O(n) ... is O(n²)!
    out = []
    for x in nums:                    # n iterations
        if x not in out:              #   × O(n) scan of a LIST
            out.append(x)
    return out

def dedupe_linear(nums):              # O(n): dict keeps insertion order
    return list(dict.fromkeys(nums))

print(has_duplicate_slow([1, 2, 3, 1]))         # True
print(has_duplicate_fast([1, 2, 3, 4]))         # False
print(dedupe_hidden_quadratic([3, 1, 3, 2, 1])) # [3, 1, 2]
print(dedupe_linear([3, 1, 3, 2, 1]))           # [3, 1, 2]

You can also simply count. Instrument the loops and watch how the counters grow when n grows 10×: the linear counter grows 10×, the quadratic one 100×, the logarithmic one barely moves.

PYTHON — Counting Operations Empirically
def count_ops(n):
    ops = {"log": 0, "linear": 0, "quadratic": 0}
    k = n
    while k > 1:              # halving loop
        k //= 2
        ops["log"] += 1
    for i in range(n):        # single loop
        ops["linear"] += 1
    for i in range(n):        # nested loops
        for j in range(n):
            ops["quadratic"] += 1
    return ops

for n in (10, 100, 1000):
    print(n, count_ops(n))
# 10 {'log': 3, 'linear': 10, 'quadratic': 100}
# 100 {'log': 6, 'linear': 100, 'quadratic': 10000}
# 1000 {'log': 9, 'linear': 1000, 'quadratic': 1000000}
WHAT INPUT SIZE CAN YOU AFFORD? (Python ≈ 10⁷ simple operations / second)
  n ≤ 10           O(n!)        permutations, brute force
  n ≤ 20–25        O(2ⁿ)        subsets, bitmask DP
  n ≤ 300–500      O(n³)        triple loops, Floyd–Warshall
  n ≤ 3 000–5 000  O(n²)        all pairs, 2D DP
  n ≤ 10⁵–10⁶      O(n log n)   sorting, heaps, binary search
  n ≤ 10⁷          O(n)         one pass, hashing, two pointers
  n > 10⁸          O(log n) / O(1)  math, binary search on the answer
Interview habit: read the constraints first. n ≤ 10⁵ is the problem setter telling you “O(n²) will time out, find O(n log n) or better”.
CONCEPT 03

Space Complexity

Space complexity counts the extra memory an algorithm needs beyond its input (often called auxiliary space). Three sources to look for: new containers you build (a set, a copied list, a DP table), slices (every a[i:j] is a new list of size j−i) and the recursion call stack (each pending call holds a frame, so recursion depth d costs O(d)).

PYTHON — Same Task, Different Space
def reverse_copy(nums):           # O(n) extra space: builds a new list
    return nums[::-1]

def reverse_in_place(nums):       # O(1) extra space: two pointers swap
    i, j = 0, len(nums) - 1
    while i < j:
        nums[i], nums[j] = nums[j], nums[i]
        i += 1
        j -= 1

def sum_recursive(nums, i=0):     # O(n) space: n frames on the call stack
    if i == len(nums):
        return 0
    return nums[i] + sum_recursive(nums, i + 1)

def sum_slicing(nums):            # O(n²) time AND space: every slice copies!
    if not nums:
        return 0
    return nums[0] + sum_slicing(nums[1:])

data = [1, 2, 3, 4]
print(reverse_copy(data), data)   # [4, 3, 2, 1] [1, 2, 3, 4]
reverse_in_place(data)
print(data)                       # [4, 3, 2, 1]
print(sum_recursive(data), sum_slicing(data))   # 10 10
Recursion limit: CPython stops recursion at about 1000 frames (RecursionError). For a DFS over 10⁵ nodes either convert to an explicit stack or call sys.setrecursionlimit(10**6) — see the cheat sheet.

Why “O(1)*” for append? A list over-allocates. Most appends just write into spare capacity; occasionally the list is copied to a bigger block. Averaged over many appends the cost per append is constant — amortized O(1).

CONCEPT 05

Mutability, References & Copies

A Python variable is a name attached to an object, not a box holding a value. Assignment never copies — it attaches another name to the same object. That only matters for mutable objects (list, dict, set, objects); int, str and tuple are immutable, so “changing” them always creates a new object.

TWO NAMES, ONE LIST
   a ──┐
       ├──►  [ 1 | 2 | 3 | 4 ]      b = a       →  no copy, same object
   b ──┘                             a is b      →  True

   c ─────►  [ 1 | 2 | 3 | 4 ]      c = a[:]    →  new object, equal values
                                     a == c      →  True   (same values)
                                     a is c      →  False  (different objects)
PYTHON — Aliasing, is vs ==
a = [1, 2, 3]
b = a                 # b is a second NAME for the same list
b.append(4)
print(a)              # [1, 2, 3, 4]   a changed too!
print(a is b)         # True   same object
c = [1, 2, 3, 4]
print(a == c, a is c) # True False   equal values, different objects

def add_one(lst):     # functions receive a reference, not a copy
    lst.append(1)
add_one(c)
print(c)              # [1, 2, 3, 4, 1]

x = None
print(x is None)      # True   compare with None using `is`, never ==

== asks “equal values?”, is asks “the very same object?”. Use is only for None (and sentinels). Never write if n is 1000 — small integers happen to be cached, big ones are not, so the result is an implementation accident.

PYTHON — Shallow vs Deep Copy
import copy

grid = [[1, 2], [3, 4]]
shallow = grid[:]            # same as list(grid) or grid.copy()
deep = copy.deepcopy(grid)   # copies the inner lists too
grid[0][0] = 99
print(shallow[0][0])         # 99   inner lists are SHARED
print(deep[0][0])            # 1    fully independent
rows_copy = [row[:] for row in grid]   # fast deep copy for a 2D grid of numbers
print(rows_copy == grid, rows_copy[0] is grid[0])   # True False
PYTHON — The [[0] * n] * m Trap
bad = [[0] * 3] * 2              # a list holding the SAME row twice
bad[0][0] = 1
print(bad)                       # [[1, 0, 0], [1, 0, 0]]
print(bad[0] is bad[1])          # True

good = [[0] * 3 for _ in range(2)]   # a brand-new row each iteration
good[0][0] = 1
print(good)                      # [[1, 0, 0], [0, 0, 0]]
# [0] * 3 on its own is fine: ints are immutable, so sharing them is harmless
PYTHON — Mutable Default Arguments
def add_item(x, bucket=[]):      # BUG: the default list is created ONCE
    bucket.append(x)
    return bucket

print(add_item(1))               # [1]
print(add_item(2))               # [1, 2]   the same list again!

def add_item_fixed(x, bucket=None):
    if bucket is None:           # create a fresh list on every call
        bucket = []
    bucket.append(x)
    return bucket

print(add_item_fixed(1))         # [1]
print(add_item_fixed(2))         # [2]
Where this bites in DSA: backtracking. You keep one path list, append / recurse / pop. When you record a result you must store a copy — res.append(path[:]) — otherwise every saved result is the same list that ends up empty.
CONCEPT 06

Loops, Comprehensions, Slicing & Unpacking

Idiomatic Python loops over values, not indices. Reach for enumerate when you need the index too, zip to walk sequences in lockstep and reversed to go backwards without copying. range(start, stop, step) excludes stop.

PYTHON — range, enumerate, zip, reversed
nums = [10, 20, 30]

print(list(range(3)))               # [0, 1, 2]
print(list(range(2, 10, 3)))        # [2, 5, 8]
print(list(range(len(nums) - 1, -1, -1)))   # [2, 1, 0]   indices backwards

for i, x in enumerate(nums):        # prints 0 10, then 1 20, then 2 30
    print(i, x)

names = ["a", "b", "c"]
print(list(zip(names, nums)))       # [('a', 10), ('b', 20), ('c', 30)]
print(list(zip(nums, nums[1:])))    # [(10, 20), (20, 30)]   adjacent pairs

print(list(reversed(nums)))         # [30, 20, 10]   reversed() is a lazy iterator
for i, x in enumerate(nums, start=1):
    pass                            # enumerate can start counting at 1

for x in nums:
    if x == 20:
        print("found")              # found
        break
else:                               # runs only if the loop did NOT break
    print("not found")
PYTHON — Comprehensions
squares = [x * x for x in range(5)]
evens = [x for x in range(10) if x % 2 == 0]

print(total)      # 30

a = [0, 1, 2, 3, 4, 5]

CONCEPT 07

Numbers: inf, Integer Division, Big Integers

Three number facts that differ from C, Java and most other languages: / always returns a float, // and % floor toward negative infinity, and integers have unlimited precision — no overflow, ever. Use float('inf') as the “bigger than anything” starting value for minimums.

PYTHON — inf, // and %, Big Integers
best = float("inf")          # larger than every number
for x in [7, 3, 9]:
    best = min(best, x)
print(best)                  # 3
print(float("-inf") < -10**18)   # True

print(7 / 2)                 # 3.5     / is ALWAYS float division
print(7 // 2, 7 % 2)         # 3 1
print(-7 // 2, -7 % 2)       # -4 1    floors toward -inf (C and Java give -3, -1)
print(int(-7 / 2))           # -3      truncate toward 0 when you need that
print(divmod(17, 5))         # (3, 2)  quotient and remainder at once
print((0 - 1) % 5)           # 4       wrap-around index in a circular array
print(-(-7 // 2))            # 4       ceiling division without floats

print(2 ** 100)              # 1267650600228229401496703205376
print(10**18 + 1 > 10**18)   # True    ints never overflow
print(0.1 + 0.2 == 0.3)      # False   floats are approximate
print(abs(0.1 + 0.2 - 0.3) < 1e-9)   # True    compare floats with a tolerance
Big ints aren't free: arithmetic on huge integers costs time proportional to their number of digits. When a problem says “return the answer modulo 10⁹+7”, take % MOD at every step to keep numbers small.
CONCEPT 08

Functions, Lambdas & nonlocal

Functions are defined with def, can return several values (as a tuple), accept default and keyword arguments, and can carry type hints — ignored at runtime, but they make interview code self-documenting. On Python 3.7 import List, Dict, Optional from typing; the built-in list[int] spelling needs 3.9+.

PYTHON — def, Type Hints, Multiple Returns
from typing import List, Optional

def binary_search(nums: List[int], target: int) -> int:
    """Return the index of target in sorted nums, or -1."""
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

def min_max(nums: List[int]) -> Optional[tuple]:
    if not nums:
        return None
    return min(nums), max(nums)      # a tuple of two values

def greet(name, greeting="hi"):      # default argument
    return greeting + " " + name

print(binary_search([1, 3, 5, 7], 5))    # 2
lo, hi = min_max([4, 9, 1])
print(lo, hi)                            # 1 9
print(min_max([]))                       # None
print(greet("ana"), greet("bo", greeting="yo"))   # hi ana yo bo

A lambda is a one-expression anonymous function. Its main job in DSA is the key= argument of sorted, min, max and heapq.nlargest. Return a tuple from the key to sort by several fields; negate a number to reverse just that field.

PYTHON — Lambdas as Sort Keys
words = ["kiwi", "fig", "banana", "apple"]
print(sorted(words, key=len))                     # ['fig', 'kiwi', 'apple', 'banana']
print(sorted(words, key=lambda w: (-len(w), w)))  # ['banana', 'apple', 'kiwi', 'fig']

intervals = [[5, 6], [1, 3], [2, 4]]
intervals.sort(key=lambda iv: iv[0])              # sort in place by start
print(intervals)                                  # [[1, 3], [2, 4], [5, 6]]

print(max([3, -7, 5], key=abs))                   # -7
counts = {"a": 3, "b": 5, "c": 1}
print(max(counts, key=counts.get))                # b   key with the largest value

Recursive helpers are usually written as nested functions so they can see the outer function's variables (grid, rows, seen…) without passing them around. Reading an outer variable or mutating an outer list/set is fine. But rebinding it — count += 1, best = max(best, x) — makes Python treat the name as a new local, which raises UnboundLocalError. Declare it nonlocal.

PYTHON — The UnboundLocalError and nonlocal
def broken():
    total = 0
    def add():
        total += 1        # assignment makes `total` local to add()
    try:
        add()
    except UnboundLocalError as e:
        print("Error:", e)

def fixed():
    total = 0
    def add():
        nonlocal total    # refer to fixed()'s `total`
        total += 1
    add()
    add()
    return total

broken()                  # Error: local variable 'total' referenced before assignment
print(fixed())            # 2
PYTHON — nonlocal in a Real DFS (Count Islands and the Largest Area)
def island_stats(grid):
    rows, cols = len(grid), len(grid[0])
    size = 0                          # area of the island being explored

    def dfs(r, c):
        nonlocal size                 # we REBIND size, so it must be nonlocal
        if not (0 <= r < rows and 0 <= c < cols) or grid[r][c] != "1":
            return
        grid[r][c] = "0"              # mutating grid needs no declaration
        size += 1
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            dfs(r + dr, c + dc)

    count, largest = 0, 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == "1":
                size = 0
                dfs(r, c)
                count += 1
                largest = max(largest, size)
    return count, largest

grid = [list("11000"),
        list("11011"),
        list("00010")]
print(island_stats(grid))   # (2, 4)
Alternatives to nonlocal: return the value from the helper (return 1 + sum(dfs(...) for ...)), store it in a mutable container (best = [0] then best[0] = ...), or use an attribute (self.best) in class-based LeetCode solutions.
CONCEPT 09

Reading Input Fast (Competitive Programming)

On judges like Codeforces, AtCoder or SPOJ you read from standard input. The built-in input() is slow for 10⁵+ lines; sys.stdin.readline is several times faster, and reading everything at once with sys.stdin.buffer.read().split() is fastest. Likewise, collect output in a list and write it once instead of calling print 10⁵ times. (LeetCode-style platforms call your function directly, so you don't need this there.)

PYTHON — Line by Line with sys.stdin.readline
import sys
input = sys.stdin.readline          # shadow the slow built-in

n = int(input())                    # int() ignores the trailing newline
nums = list(map(int, input().split()))
q = int(input())
queries = [tuple(map(int, input().split())) for _ in range(q)]

prefix = [0]
for x in nums:
    prefix.append(prefix[-1] + x)   # prefix[i] = sum of first i numbers

out = []
for l, r in queries:                # sum of nums[l..r], 0-indexed, inclusive
    out.append(prefix[r + 1] - prefix[l])
sys.stdout.write("\n".join(map(str, out)) + "\n")   # one write, not many prints

# 1 2 3 4 5         14

PYTHON — All Tokens at Once (Fastest)
import sys

def main():
    data = sys.stdin.buffer.read().split()   # every whitespace-separated token
    n = int(data[0])
    nums = list(map(int, data[1:1 + n]))
    print(sum(nums), max(nums))

main()

# stdin:  3            stdout:  60 30
#         10 20 30
Gotchas: readline() keeps the trailing \n — call .strip() before using a line as a string (int() and .split() don't care). buffer.read() returns bytes; decode tokens with .decode() if you need strings. Wrapping your code in main() also makes it a bit faster, because local variable access is quicker than global.
